# fast_forward 设计方案与微架构说明

> 顶层模块名：`dut`（与 `design/syn/rpt/dut.hier.area` 报告名一致；如考试环境顶层名不同，改 module 名即可）
> RTL：`rtl/dut.sv`（单文件，可综合 SystemVerilog）

---

## 1. 得分模型与总体策略

得分公式：**score = (1/T)^4 × (1/Power) × (1/Area)**，时钟周期下限 0.4ns。

- T 的权重是 4 次方，**性能（吞吐）优先**是第一设计原则：任何 bkpr 反压拍、任何依赖链上多余的 1 拍，都直接放大到 4 次方。
- 性能用例只保留中载/重载；重载下入口速率为 4 pkt/cycle，出口上限也是 4 pkt/cycle（4 lane 循环保序）——**理想 T 就是"永不反压 + 依赖不断流"**。
- 依赖占比 1/3（3bit 域按 14:1:1:1:1:1:1:1 分布），依赖处理路径是重载吞吐的决定因素。
- Area/Power 各只有 1 次方：FE 单价约 3500um²，在 T^4 面前，用 FE 数量和 ROB 深度换吞吐是划算的，但要避免无谓的大 mux/多写口。

最终配置：**8 个 FE + 64 深 ROB + 乱序发射 + 预唤醒**，实测重载吞吐 **3.85 pkt/cycle**（理想值 4.0 的 96%，含反压与统计噪声），中载 **2.0 pkt/cycle**（输入受限的理想值）。

## 2. 架构总览

```
PKTIN(4 lane) ──► S0 输入寄存 ──► S1 压缩+分配(alloc)
                                      │  写入 ROB[seq mod 64]
                                      ▼
        ┌──────────────────────── ROB 64 × {data128, lat2, tgt6, isdep, 状态位}
        │   状态: rdy / wtg / issued / resv / outp
        │
        │  I0 pick: 8 个发射口 = {lat类(4) × 奇偶(2)}，各自独立
        │           在 (rdy|预唤醒) 位图上按龄选首个候选
        │  I1 issue: 读 ROB data + 依赖目标 data(dp) → FEIN
        ▼
   FE0..7 (黑盒, lat类绑定: FE[2L+p] 只收 latency=L+1 的报文)
        │            tag pipe(每FE定长延迟线) 跟踪在途报文的 ROB 索引
        ▼
   FEOUT ──► 结果写回 ROB[tag]（每表项写源唯一）
        │      ├─ 预唤醒: tag pipe 倒数第2级预测下一拍出结果 → 提前 pick 依赖报文
        │      └─ dp bypass: 依赖报文发射当拍直接从 FEOUT 总线取 dp_data
        ▼
   输出级: 从 out_seq 连续弹出 ≤4 个已完成表项(含当拍结果 bypass)
           lane = seq[1:0] ──► PKTOUT 寄存输出
   BKPR: 占用度/发射窗口 双阈值，寄存输出
```

报文全生命周期（独立报文、重载）：外部驱动 t → 输入寄存 t+1（alloc）→ pick t+2 → FEIN t+3 → FEOUT t+3+lat（lat=1..4）→ **同拍**弹出 → PKTOUT 寄存 t+4+lat。

## 3. 关键机制

### 3.1 序号、ROB 与 lane 映射
- 每个到达报文按 lane0→lane3 的顺序取全局序号 `seq`（7bit 计数器，含 wrap 位），ROB 表项 = `seq mod 64`。
- 题目规定出口 lane 严格循环递增，等价于 **输出 lane = seq[1:0]**：每条输出 lane 的数据 mux 只需覆盖 16 个表项（idx[1:0] 固定），面积最小。
- 输入侧先做"有效 lane 压缩"，再按 `alloc_seq[1:0]` 旋转对位，使 **表项 e 的输入写源固定为槽 e[1:0]** ——每个表项的输入侧写 mux 只有 1 个来源。

### 3.2 FE 组织：lat 类 × 奇偶 绑定（本设计的核心简化）
FE 编号 `f = {lat类 L(2bit), 奇偶 p(1bit)} = 2L+p`：

1. **FE f 只接收 latency 域 = L 的报文**。同一 FE 内报文延时恒定 → 输出端**结构上不可能冲突**，完全不需要 busy/时隙跟踪逻辑；每个 FE 的在途 tag 跟踪退化为一条定长(L+1)延迟线。
2. **奇偶 p = ROB 表项索引 bit0**。表项 e 的结果只可能来自 FE `{rob_lat[e], e[0]}` → 每个表项的**结果写源唯一**（4 选 1 由存储的 lat 静态选择），彻底避免了"8 个 FE 结果总线 × 64 表项"的巨型写 mux。
3. 8 个发射口的候选集合按 (L,p) **天然互斥划分**，端口间零仲裁逻辑。
4. 容量：每类 (L,p) 平均到达率 = 4×(1/4)×(1/2) = 0.5 pkt/cycle，服务率 1 → 利用率 0.5，突发由 ROB 吸收。

代价：同类同奇偶的两个就绪报文同拍只能发 1 个（概率低，由 ROB 吸收）；换来的是调度/仲裁/互连逻辑数量级的缩减——这正是 0.4ns 下能收敛的关键。

### 3.3 乱序发射（OoO issue）
- 每表项状态机：`alloc → (rdy | wtg) → picked/issued → resv(结果到) → outp(已输出)`。
- I0 pick：对每个发射口，将其候选位图按 `oldest_unissued` 旋转到年龄序，优先编码取最老者；二进制位置 + 基址还原索引（避免 one-hot 反旋转）。
- 非依赖报文永不被前方等待的依赖报文阻塞；输出保序完全由 ROB 兜底。

### 3.4 依赖处理（吞吐关键路径）
- alloc 时计算目标表项 `tgt = (seq - dep) mod 64`：
  - 目标是**同拍早 lane** 报文（dep ≤ 拍内位置）→ 必然未完成，置 `wtg`；
  - 目标结果已在（`resv`，含**当拍写回**、含**下一拍预测**）→ 直接 `rdy`；
  - 否则 `wtg` 并记录 `tgt`，等待唤醒。
- **预唤醒（pre-wake）**：tag pipe 是确定性延迟线，倒数第 2 级即"下一拍必出结果"。据此提前一拍唤醒/pick 依赖报文，使其 **与目标结果同拍进入 FE**（题目原文：“B 才能和 A_fwd 一起，在同一个 cycle，一起送入 B 去往的转发单元”）。
- **dp bypass**：依赖报文发射当拍，若目标结果恰好当拍出现在 FEOUT，`dp_data` 直接从 FEOUT 总线组合旁路（FEIN/FEOUT 为内部接口，题目明确无寄存约束）。
- 依赖链每级延迟 = 目标的 FE 延时（最优下界）：目标 lat=1 时，B 恰好晚 A 一拍发射。
- **结果保留**：目标报文即使已从 PKTOUT 输出，其转发结果仍保留在 ROB 表项中（`outp` 标志与 `resv` 分离），直到表项被 +64 序号重新分配——覆盖"目标早已输出、依赖报文迟到"的场景。

### 3.5 反压（BKPR）与重分配 hazard 窗口（正确性证明要点）
BKPR 为寄存输出、PKTIN 必须先寄存 → 从组合判断到真正止流有 **2 拍、最多 8 个**未计入的在途报文。两个守卫（均按 mod-128 序号差比较）：

1. **占用度**：新序号 n 复用表项 (n-64)，要求 n-64 已输出：`alloc_next - out_seq > 64-1-8 = 55` 时反压。
2. **发射窗口**：表项重分配会摧毁旧结果，而依赖窗口=7，序号 ≤ n-64+7 的报文发射时可能还要读它 → 要求它们**全部已发射**：`alloc_next - oldest_unissued > 64-7-8-4(流水裕量) = 45` 时反压。

`oldest_unissued` 指针用"~issued 旋转 + 优先编码"一拍全速追赶，不引入人为窗口损失。

> 调试记录：初版阈值只留 4 个裕量（1 拍），重载下出现表项被 +64 报文结果覆盖的错值（TB 抓到输出了 seq+64 的 gold 值），修为 8 后归零——这就是上述 2 拍推导的实证。

### 3.6 输出级
- 从 `out_seq` 起连续检查 ≤4 个表项 `(resv|res_now) & ~outp`，**当拍写回的结果同拍即可弹出**（数据走 FEOUT 旁路 mux），省 1 拍占用；
- 弹出映射到 lane=idx[1:0]，PKTOUT 寄存输出，天然满足循环保序。

## 4. 时序设计（0.4ns 目标）

各时序级的逻辑深度控制：

| 级 | 关键路径 | 估计深度 |
|---|---|---|
| S1 alloc | 输入FF → 16路压缩case → 旋转 → 表项写使能/初始状态 → FF | ~10–12 级 |
| I0 pick | (预测唤醒 5b 比较) → 候选位图 → 64b 旋转(6级mux) → 64b 优先编码(~7级) → +基址 → FF | ~18–20 级（最紧） |
| I1 issue | pick FF → 32:1/64:1 数据 mux → FEIN（FE 内部首级 FF 收口） | ~8–10 级 |
| 写回 | FEOUT FF → 4:1 → 表项 FF | 短 |
| 输出 | 状态位 → pop 计数 → 16:1 lane mux + bypass → PKTOUT FF | ~10 级 |

时序收敛备用挡位（均已验证功能正确）：
- `WAKE_BYPASS=0`：切断"预测唤醒 → 当拍 pick"组合链，依赖链每级 +1 拍；
- `REG_FEIN=1`：FEIN 出口加一级寄存（若 fe.v 输入级时序紧张），整体延迟 +1 拍；
- ROB 深度 `D`（localparam，需 2 的幂）：64→32 可缩短旋转/优先编码 1 级并省一半存储，重载吞吐约降至 ~3.4（阈值公式已参数化，自动跟随）。

综合建议：`compile_ultra` + 允许 retiming；ROB 数据阵列写使能已按表项独立（综合器可自动插 ICG）；pick 逻辑集中在 I0 一级，必要时可对 `pe` 优先编码指定 parallel 结构。

## 5. 面积 / 功耗

面积构成（自身逻辑）：
- 存储主体：ROB 64×128b 数据 + 64×~10b 控制 ≈ 8.8k FF（数据 FF 无复位、全部写使能门控）；
- 大 mux 已被三个结构决策压到最低：输入写源唯一（1 源）、结果写源唯一（4 选 1）、输出 lane mux 16:1；发射数据 mux 为 8×(32:1×128b) + 8×(64:1×128b dp)。
- 8 × FE ≈ 28k um²。

功耗：
- 所有 128b 数据寄存器（输入寄存、ROB、PKTOUT、FEIN 保持寄存）均使能门控，空闲/轻载时数据通路零翻转；
- FEIN 数据在 vld=0 时保持上一值（pick 索引寄存器带使能），不向 FE 灌翻转；
- 控制位图为 1bit 逻辑，规模小。

若评分实测中面积/功耗占比过高，第一优先降档是 `D=32`（省 ~4.4k FF），其次 FE 8→4（改为每 lat 类 1 个 FE，去掉奇偶维度；吞吐约降 8–12%，需实测权衡 T^4 与 A·P）。

## 6. 验证

自建环境（`verif/`，Verilator 5）：
- `fe_model.sv`：FE 行为模型——无阻塞流水线、lat+1 拍延时、**输出冲突检测**（两包同拍成熟即报错）、变换函数 f(data, dp)（黑盒占位，金模型同函数，端到端数据比对可验证 DUT 全部搬运逻辑）。
- `tb_top.sv` 检查点：
  1. FEIN 协议：每报文恰好发射一次、data/lat 正确；依赖报文必须 dp_vld=1、dp_data == 目标的转发结果、且不早于目标结果在 FEOUT 出现的时刻；非依赖报文 dp_vld=0；
  2. FEOUT：结果必须恰好在 FEIN 后 lat+1 拍出现（同时校验无输出冲突）；
  3. PKTOUT：按 lane0→3 循环严格保序比对金数据，非连续 lane 有效即报错；
  4. BKPR：生成器同拍采样并止流（题目语义）。
- 激励：官方依赖分布 14:1×7、lat 均匀 1–4、可调负载/包数/种子；另有 7/8 依赖占比的极限压力模式（`+DEPHEAVY=1`）。

结果（全部 PASS，0 错误）：

| 用例 | 配置 | 吞吐 (pkt/cycle) |
|---|---|---|
| 重载长跑 | 20k 包, 100% load | **3.848** |
| 中载长跑 | 20k 包, 50% load | 1.999（输入受限理想值） |
| 重载×8 种子 | 2k 包 | 3.63–3.77（含尾部排空） |
| 依赖极限压力 | 5k 包, 7/8 依赖 | 2.31（正确性无损） |
| 稀疏负载 | 20% load | PASS |
| REG_FEIN=1 / WAKE_BYPASS=0 | 重载+压力 | PASS |

复现：`make quick / mid / heavy`；参数 `+NPKT= +LOADPCT= +SEED= +DEPHEAVY=`。

## 7. 对接考试环境注意事项

1. 端口名/位宽严格按题目表实现（`lane{0..3}_pkt_in_*`、`fwd{0..7}_*`、`fwded{0..7}_*`、`pkt_in_bkpr`）；采用 8 个 FE，例化 fe.v 8 份即可。
2. `fwd*_pkt_lat` 按绑定关系为常数（FE0/1=0, FE2/3=1, FE4/5=2, FE6/7=3），属题目允许的"设计者保证输出冲突"策略。
3. 真实 fe.v 的变换与本地 fe_model 不同不影响 DUT（DUT 不触碰数据内容，纯搬运）；接入后建议先跑 tc 基础用例，若环境对"依赖报文与目标结果同拍进 FE"报协议错误，将 `WAKE_BYPASS` 置 0（每链级 +1 拍）。
4. 若 fe.v 输入端时序收敛困难，置 `REG_FEIN=1`。
5. 本地临时跑 tc_perf 可按题目说明改 `verification/tc/tc_perf.sv` 第 64 行 outstanding 发包数。
